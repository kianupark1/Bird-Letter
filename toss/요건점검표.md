> 근거: 공식 문서(developers-apps-in-toss.toss.im)를 WebFetch로 직접 읽은 내용 + `C:\bl` 코드(src/, core/, firebase/) 대조.
> 표시: **충족 / 부족 / 해당 없음 / 확인 필요**. 코드를 읽어서 안 것은 근거 `파일:줄`을 적었고, 실제 토스 앱·빌드로 돌려 보지 않은 것은 "확인 필요"로 뒀습니다.
> 작업량: 작음(반나절 이내) / 중간(1~2일) / 큼(며칠 이상). 대략적인 감이며 숫자로 검증한 값은 아닙니다.
> 읽은 공식 문서: `checklist/app-nongame`(비게임 출시 체크리스트), `intro/guide`(서비스 오픈 정책), `intro/caution`(서비스별 주의사항), `guide/operation/console-workspace`(앱 등록·스크린샷), `guide/operation/toss`(번들 업로드·ait), `guide/authentication/intro`·`anon-key`, `documentation/integration/server-api`, `guide/faq`. 일부 페이지(Next.js 정적 빌드, NavigationBar.setOptions 상세, 토스 로그인 개발 연동, Firebase 연동 가이드, CORS Origin 값)는 요약만 나오거나 내용이 안 나와서 "확인 필요"로 남겼습니다.

## 먼저 알아 둘 큰 그림

1. **새편지는 지금 Next.js 서버 렌더링 구조라 그대로는 못 올립니다.** `next.config.mjs:1-2`가 빈 설정이고, 편지 화면이 동적 경로(`src/app/letter/[id]/page.tsx`)입니다. 공식 문서는 SSR 금지, CSR 또는 정적 생성(SSG)만 허용합니다. 가장 큰 공사입니다.
2. **`toss/` 폴더에는 로고와 문구 파일뿐입니다.** 앱인토스 SDK 설치, `granite.config.ts`, 빌드 설정이 아직 없습니다.
3. **"토스 로그인"과 "사용자 식별키"는 다른 것입니다.** 공식 문서상 식별키(`getAnonymousKey`)는 서버 연동·동의 화면 없이 얻고, 토스 로그인(사용자 정보 받기)은 앱인토스 서버 API(mTLS 인증서)가 필요해 내 서버가 있어야 합니다. 새편지에 토스 로그인이 꼭 필요한지는 문서로 확정하지 못했습니다(확인 필요).
