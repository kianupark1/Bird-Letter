# Firebase 설계 (초안)

## 목표
- 웹과 앱인토스 두 버전이 **같은 서버**를 쓴다.
- 계정이 없어도 편지를 쓰고 받을 수 있다(익명 로그인 → 나중에 카카오/토스 계정으로 연결).
- 앱인토스 요건: 사용자 식별자 저장·데이터 유지, **신고·차단**, **탈퇴 시 삭제**, 개인정보 암호화(전송은 HTTPS, 저장은 Firebase 기본 암호화).

## 데이터 구조
| 위치 | 내용 |
|---|---|
| `users/{uid}` | 닉네임, 알림 설정 |
| `users/{uid}/blocks/{차단한사람uid}` | 내 차단 목록 |
| `letters/{편지ID}` | 겉정보: fromUid, fromName, toName, routeId, birdId, sentAt, arriveAt, recipientUid |
| `letters/{편지ID}/private/body` | 편지 내용(message) — **도착 시각 전에는 보낸 사람 말고는 못 읽음** |
| `reports/{id}` | 신고(쓰기 전용) |

- 편지 ID는 길고 무작위 문자열이라서 **초대 링크 자체**가 된다: `https://…/r/{편지ID}`.
- 링크를 연 사람은 익명 로그인 후 "받는 사람"으로 한 번 등록되고, 그 뒤 자기 받은 편지함에서 볼 수 있다.

## "느린 배달"을 서버 없이 지키는 방법
- 보안 규칙이 `arriveAt <= 현재 서버 시각`일 때만 편지 내용을 읽게 한다. 앱 화면을 조작해도 도착 전에는 내용을 가져올 수 없다.
- 도착 시각은 보낼 때 정해지고, 현재 규칙은 "보낸 시각보다 뒤"인지만 검사한다(새 종류별 속도까지 규칙에서 검증하지는 않음 → 보낸 사람이 자기 편지를 빨리 도착시키는 것은 막지 못함. 정식 출시 전에 Cloud Functions로 보강할지 결정).

## 신고·차단·탈퇴
- **신고:** `reports`에 쓰기. 운영자가 Firebase 콘솔에서 확인.
- **차단:** 내 `blocks`에 추가 → 받은 편지함에서 그 사람의 편지를 숨김(화면 단계).
- **탈퇴:** 내 편지(내용 포함)와 `users/{uid}`를 지우고 인증 계정을 삭제. 모두 앱에서 직접 실행(서버 함수 불필요).

## 비용과 한계 (정직하게)
- 지금 설계는 Firebase **무료(Spark) 플랜**으로 시작할 수 있다.
- 아래는 **유료(Blaze, 사용량만큼 과금, 카드 등록 필요) 플랜이 필요**해질 수 있다:
  - 정해진 시각에 **푸시 알림을 서버에서 보내기** (Cloud Functions + 스케줄러)
  - **토스 로그인 → Firebase 로그인 연결** (서버에서 토큰 교환)
  - 도착 시각을 서버에서 검증하기
- 위 기능은 필요해지는 시점에 사용자와 상의 후 결정한다.

## 적용 순서
1. 웹 앱 등록 ✓ (사용자가 완료)
2. Authentication → 익명 로그인 켜기
3. Firestore(서울) 확인 후 `firebase/firestore.rules` 붙여넣기
4. 코드: 설정값을 `.env.local`에 넣고, 편지 저장소를 "내 폰 저장" → "Firebase"로 교체(실패 시 내 폰 저장으로 되돌아가게)
5. 라이브로 테스트(두 브라우저로 보내기·받기·도착 전 읽기 차단 확인), 그 뒤 규칙 확정

> 보안 규칙은 아직 실제 Firebase에서 시험하지 않은 **초안**이다. 4~5단계의 라이브 테스트를 거쳐야 믿을 수 있다.
