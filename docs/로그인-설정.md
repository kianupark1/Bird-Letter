# 소셜 로그인 5종 연결 준비 (구글·카카오·네이버·애플·라인) · 2026-10-13

> 목표: 한국에서 시작해서 일본·중국 등으로 넓히는 것을 전제로 **구글·카카오·네이버·애플·라인을 모두 "연결"로 제공**해요(가입이 아니라 익명 계정에 연결).
> 이 문서는 **준비서**예요. 실제 키 발급과 코드 연결은 대표님이 키를 받으신 뒤에 한 단계씩 같이 해요.
> 「미확인」은 제가 아직 공식 문서로 확인하지 못한 부분이에요.

## 1. 큰 그림
| 로그인 | 연결 방식 | 서버 필요 | 대표님이 발급할 것 |
|---|---|---|---|
| **구글** | Firebase가 기본 지원 | 없음 | Firebase 콘솔에서 켜기, 승인된 도메인 추가 |
| **애플** | Firebase가 기본 지원 | 없음 | 애플 개발자 계정 가입(15일 이후), 서비스 ID·키 발급 |
| **카카오** | 우리 서버가 카카오에 확인한 뒤 Firebase 로그인 토큰을 발급 | **필요(Vercel)** | 카카오 앱 키, 로그인 켜기, 동의항목 |
| **네이버** | 위와 같음 | **필요(Vercel)** | 네이버 앱 ID·비밀번호(시크릿) |
| **라인** | 위와 같음 | **필요(Vercel)** | LINE 채널 ID·시크릿 |

- **서버 방식(카카오·네이버·라인)**: 앱이 소셜 로그인 결과(토큰)를 우리 서버에 보내면, 서버가 해당 회사에 확인하고 Firebase "로그인 토큰"을 만들어 돌려줘요. 구글·애플 외의 로그인에 일반적으로 쓰는 방식이에요 [(카카오 예제)](https://github.com/FirebaseExtended/custom-auth-samples/blob/master/kakao) [(라인+Firebase 예)](https://zenn.dev/kosukesaigusa/articles/line-login-with-firebase-auth-by-custom-token?locale=en).
- 사용자 번호는 **"kakao:번호", "naver:번호", "line:번호"**처럼 앞에 회사 이름을 붙여서 서로 섞이지 않게 해요.
- 라인은 토큰 확인 방법(검증 주소와 nonce)이 공식 문서에 있어요 [(LINE 공식)](https://developers.line.biz/en/docs/line-login/verify-id-token).
- 서버에는 **Firebase 서비스 계정 키(비밀)**가 필요하고 Vercel 환경 변수에만 넣어요. **채팅에 붙이지 마세요.** 이 방식이 유료 전환(Blaze) 없이 되는지는 **「미확인」**이에요.

## 2. 대표님이 할 일 (키 발급 순서)
| 순서 | 일 | 링크 | 소요 | 언제 |
|---|---|---|---|---|
| 1 | **구글**: Firebase 콘솔 → Authentication → 로그인 방법 → Google 사용 설정. 승인된 도메인에 `bird-letter.vercel.app` 추가 | https://console.firebase.google.com/ | 10분 | 지금 가능 |
| 2 | **카카오**: 이미 만든 앱 "새 편지"에서 카카오 로그인 켜기, 리다이렉트 주소·도메인 등록, 동의항목(닉네임) 설정 | https://developers.kakao.com/ | 30분 | 지금 가능 |
| 3 | **네이버**: 네이버 로그인 앱 등록, 서비스 URL·콜백 주소 등록 | https://developers.naver.com/ | 30분 | 지금 가능 |
| 4 | **라인**: 프로바이더와 LINE 로그인 채널 만들기 | https://developers.line.biz/ | 30분 | 지금 가능 |
| 5 | **애플**: Sign in with Apple 설정(서비스 ID, 키) | https://developer.apple.com/ | 30분 | **애플 가입 후** |
| 6 | **Firebase 서비스 계정 키**를 Vercel 환경 변수로 넣기(제가 단계 안내) | https://vercel.com/dashboard | 15분 | 서버 코드 전 |

- 메뉴 이름은 서비스가 바꿀 수 있어서 **그 화면을 사진으로 보내주시면** 한 단계씩 짚어 드려요.
- **시크릿(비밀번호 같은 값)은 채팅에 붙이지 않아요.** ID처럼 공개되는 값만 알려주시면 되고, 시크릿은 Vercel에 직접 붙여 넣는 방법으로 안내해요.

## 3. 법·규정 확인 (조사 결과)
| 항목 | 내용 |
|---|---|
| 합법 여부 | 소셜 로그인은 합법이에요. 각 회사 약관, **개인정보 수집·이용 동의**, 처리방침 표기를 지키면 돼요 |
| 받는 정보 | **닉네임과 계정 번호만**(이메일·전화번호는 받지 않는 걸 기본). 더 받으려면 목적과 동의가 필요해요 |
| 애플 4.8 | 제3자 로그인이 있으면 **"애플로 로그인" 같은 동등한 옵션도 제공**해야 해요. 5종 모두 넣기로 해서 **애플이 포함돼 해결**돼요 [(Apple 개발자 포럼)](https://developer.apple.com/forums/thread/765145) |
| 카카오 심사 | 동의항목은 **실제 가입 화면과 처리방침을 기준으로 심사**해요. 앱이 실제로 동작하는 수준일 때 신청해야 통과 가능성이 높아요 [(카카오 데브톡)](https://devtalk.kakao.com/t/topic/150829) |
| 네이버 심사 | **「미확인」** (네이버 개발자센터 공지를 직접 확인) |
| 라인 심사 | **「미확인」** (LINE 개발자 문서 확인) |

## 4. 해외 확장 메모 (일본·중국)
- **일본:** 라인이 가장 많이 쓰여서 이미 포함돼요. 일본 이용자의 개인정보 처리 의무는 **별도 확인이 필요해요(「미확인」)**.
- **중국:** 구글 등 일부 서비스는 접속이 제한돼 있고, 현지에서는 **위챗 같은 다른 로그인**이 주로 쓰여요. 앱 심사와 서버 위치·개인정보 법규도 달라서 **지금은 로그인 5종만 만들고, 중국은 별도 조사 후 결정해요(「미확인」)**.
- **언어:** 해외 확장 때 언어 설정이 필요해요(첫 버전에서는 한국어).

## 5. 제가 만들 것 (키를 받은 뒤)
1. 설정 화면 **"계정 연결"** 섹션: 5개 버튼, 연결된 계정 표시, 연결 해제
2. 구글·애플 연결(Firebase 기본 방식)
3. 카카오·네이버·라인 서버 연결(Vercel 서버 코드, 토큰 확인, 사용자 번호 규칙, 시험)
4. 이미 쓰던 익명 계정의 **편지·친구·구매가 연결 뒤에도 그대로** 남게 하는 처리(같은 사용자 번호 유지)
5. 처리방침의 소셜 로그인 항목, **탈퇴 시 연결 정보까지 삭제**
6. 시험: 연결 → 앱을 지웠다가 다시 설치 → 같은 계정으로 연결 → 기록이 남는지

## 6. 카카오 로그인 구현 상태 (2026-10-14, 키 입력 전이라 꺼져 있음)
**코드는 끝났고, 아래 값 4개를 넣으면 켜져요.** 설정 화면의 카카오 버튼은 값이 없으면 "준비 중"으로 막혀 있어요.

| 값 | 어디서 받나 | 어디에 넣나 |
|---|---|---|
| `NEXT_PUBLIC_KAKAO_REST_KEY` | 카카오 개발자 → 내 애플리케이션 → 앱 키 → **REST API 키** (공개되는 값) | Vercel 환경 변수 |
| `KAKAO_REST_API_KEY` | 위와 같은 값 | Vercel 환경 변수(비밀) |
| `KAKAO_CLIENT_SECRET` | 카카오 로그인 → 보안 → Client Secret 을 **사용함**으로 했을 때만 | Vercel 환경 변수(비밀) |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | Firebase 콘솔 → 프로젝트 설정 → 서비스 계정 → **새 비공개 키 생성**(JSON 파일) | Vercel 환경 변수(비밀). 파일 내용 통째로 |

카카오 개발자 콘솔에서 할 설정: ① 카카오 로그인 **활성화** ② **Redirect URI**에 `https://bird-letter.vercel.app/auth/kakao` 등록 ③ 동의항목에서 **닉네임**만 ④ 플랫폼 > Web에 `https://bird-letter.vercel.app` 등록.

동작: 설정 → 카카오 → 카카오 화면 → `/auth/kakao` → 서버(`src/app/api/auth/kakao/route.ts`)가 카카오 확인 + 폰의 익명 계정 확인 → `kakaoAccounts/{카카오번호}`에 uid를 한 번만 기록(처음이면 **지금 쓰던 익명 uid 그대로 → 편지·친구 유지**, 이미 있으면 그 uid → 새 폰에서도 같은 계정) → Firebase 커스텀 토큰으로 로그인. 부품 시험: `npm run test:core` 145개(토큰 서명·확인, 카카오 흐름 9가지).

- `kakaoAccounts` 컬렉션은 **규칙에 없어서 폰에서는 읽고 쓸 수 없고**, 서버(서비스 계정)만 쓴다.
- 서비스 계정 키는 **Spark(무료) 요금제에서도 만들 수 있다**고 알고 있지만 **「미확인」**. 콘솔에서 막히면 알려 주세요.
- 한 계정에 카카오 하나만 연결(다른 카카오를 또 붙이면 409). 카카오 연결 해제는 아직 없음.
- 실제 카카오 서버와의 통신은 키가 없어서 **아직 못 시험**했다(가짜로 만든 시험만 통과).
