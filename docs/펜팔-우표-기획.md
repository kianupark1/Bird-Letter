# 펜팔 우표 기획 (2026-10-24, 대표님 결정: "우표 방식으로 가자")

대표님 생각: "받는 사람이 수락하면 처음 보내는 사람만 돈을 내고, 수락 안 하면 돈 안 냄."
앱 결제(애플·구글)는 "묶어 뒀다가 나중에 빼가기"가 안 돼서 **우표를 먼저 사고, 답이 없으면 돌려주는** 방식으로 같은 결과를 만듦.

## 규칙 (계산은 `core/penpalStamp.ts`, 시험 10개)

| 항목 | 값 | 비고 |
|---|---|---|
| 우표가 드는 편지 | 모르는 사람에게 보내는 **첫 편지**만 | 답장·이미 이어진 펜팔·친구 편지는 무료 |
| 하루 무료 | 첫 편지 **5통** (한국 자정 기준, 2026-11-03 대표님: 1통→5통) | `FREE_PER_DAY` |
| 돌려주기 | 도착 뒤 7일 안에 답장이 없으면 우표 1장 돌려줌 | `REFUND_DAYS`, "수락" = 답장 |
| 가격 | **우표 1장 500원**(2026-11-05 대표님 결정) · 묶음 할인은 숫자 본 뒤 | 애플·구글 한국 최저 가격 단계에 500원이 있는지 「미확인」 |
| 시간·확률 | 우표는 도착 시간·사고 확률과 상관없음 | 기다림의 미학·법무 원칙 |

## 2026-11-09 대표님 결정: "펜팔 우표 그냥 하자" (변호사 확인 기다리지 않고 진행)

- 남는 위험(법무팀 기록): 랜덤채팅 청소년유해매체물 고시 해당 여부·미성년자 결제(법정대리인 동의 없는 결제는 취소될 수 있음)는 확인 안 된 채로 감 「미확인」. 줄이는 장치로 같이 만듦: ①로그인 계정만 구매(익명 불가) ②펜팔 약속(만 14세 이상) 통과한 사람만 ③구매 창에 "만 19세 미만은 보호자 동의 후 구매해 주세요" ④약관에 유료·청약철회·환불 조항 ⑤앱스토어 연령 16+ 그대로.
- 순서: 결제 바탕(애플 영수증 서버 확인 `core/appleIap.ts`, 시험 9개) → 우표 지갑 서버(`users/{uid}/wallet`, 서버만 씀) → 펜팔 첫 편지 보내기를 서버 입구로(하루 무료 5통·우표 차감을 서버가 계산) → 돌려주기(지갑을 열 때 서버가 계산) → 구매 화면 → 새 앱 파일(결제 플러그인) → TestFlight 시험 결제 → 켜기.
- 대표님 몫: App Store Connect 유료 앱 계약·은행·세금 → 소규모 사업자 프로그램(수수료 15%) → 앱 내 구입 상품 `com.saepyeonji.app.stamp1`(소모성, ₩500 단계가 있는지 확인 「미확인」).
- 안드로이드는 출시 뒤 구글 결제로 같은 상품.

## 출시 순서
1. **출시 때는 무료**(우표 화면 없음, 하루 제한도 없음) → 2주 동안 하루 펜팔 첫 편지 수·답장 비율을 `/admin`으로 봄.
2. 우표 켜기 전 준비: 통신판매업 신고, 애플·구글 앱 결제 상품 등록(소모성 상품), 개인정보처리방침·약관에 결제·환불 추가, 법무 표현 점검.
3. 서버: 우표 개수는 **서버만 바꿀 수 있게**(앱이 쓴 값을 믿지 않음). 결제 영수증을 Vercel 서버가 애플·구글에 확인 → `users/{uid}/wallet`에 기록, 규칙은 읽기만 허용. 돌려주기도 서버가 매일 한 번 계산(QStash 예약).
4. 화면 시안(대표님 확인 뒤 개발): 펜팔 편지 화면 "오늘 무료 5통 중 N통 남음 · 우표 N장", 우표가 필요할 때 아래 시트, 돌려받으면 "답이 없어서 우표를 돌려드렸어요 🕊".

## 하지 않는 것
- 성별 칸·이성 필터: 데이팅 분류·랜덤채팅 고시·범죄 악용 위험 → 법무·성인 본인인증 전에는 안 함.
- 우표로 빨리 보내기·사고 면제: 시간·확률을 돈으로 사는 상품 금지.

## 수익 영향
