## 2. 그대로 다시 쓸 수 있는 기술 틀

## 3. 앱마다 새로 해야 하는 것 (순서대로)

1. **앱 ID(번들 ID) 정하기** — 예: `com.brunosono.bible` 같은 형태. **등록 뒤 못 바꿈**.
2. **GitHub 저장소** 새로(공개 저장소면 비밀 값·개인정보 절대 커밋 금지).
3. **Firebase 프로젝트** 새로(서울 리전) → 로그인 방법(구글·애플·익명) 켜기 → **승인된 도메인에 새 Vercel 주소 추가**(안 하면 웹 구글 로그인 안 됨) → 아이폰 앱 등록(`GoogleService-Info.plist`, 구글 로그인 켠 **뒤에** 받은 파일이어야 `CLIENT_ID`가 들어 있음) → 안드로이드 앱 등록(`google-services.json`, **플레이 앱 서명 SHA-1·SHA-256 넣은 뒤** 다시 받아야 구글 로그인 됨).
4. **Vercel 프로젝트** 새로 + 환경 변수.
5. **애플**: developer.apple.com에서 번들 ID 등록(Push·Sign in with Apple 켬) → App Store Connect에서 앱 만들기 → 알림 열쇠(APNs .p8)를 Firebase에 올리기(같은 계정 열쇠 재사용 가능).
6. **구글 플레이**: 앱 만들기 → 앱 콘텐츠 12개 → 스토어 등록정보(아이콘 512, 그래픽 1024×500, 폰 사진) → 내부 테스트 → **비공개 테스트 12명 이상×14일**(새편지는 크몽 zardu 5,000원으로 해결, 테스트 중 같은 비공개 트랙 업데이트 1번 이상 하면 통과율이 높다고 함) → 프로덕션 신청.
7. **카카오 로그인 쓸 거면**: 카카오 개발자 앱 새로(앱 아이콘 등록, 동의항목 닉네임·프로필 사진, Redirect URI, 플랫폼에 iOS 번들 ID·Android 패키지+키 해시 2개(업로드 키·플레이 서명 키)).
8. **SNS 계정**(앱 이름 아이디) → Meta 앱에 테스터로 넣고 열쇠 받기(새편지 때 순서 그대로).

## 4. 심사에서 실제로 겪은 것 (같은 실수 안 하게)

### 애플
- **4.2(웹 껍데기만 있는 앱) 반려 위험** → 앱 알림·계정 삭제·공유·연락처 같은 "앱다운 기능"을 넣었고 1.1은 통과.
- **2.1 앱 완성도로 반려(1.2, 2026-11-11)**: 심사 중 앱이 꺼진 기록 2개. → 출시 전에 시뮬레이터 점검(`ios-sim-check.yml`)으로 첫 실행 꺼짐 확인 필수.
- **아이패드 화면 사진 요구로 막힘** → 아이폰 전용으로 빌드(`TARGETED_DEVICE_FAMILY=1`).
- 화면 사진 칸: 새 화면은 "Dynamic Island 지원 iPhone(중형)" 칸, 1206×2622로 올림(1320×2868은 거절).
- 다른 소셜 로그인이 있으면 **애플 로그인도 넣어야 함**, 계정 삭제 기능 필수(애플 계정은 삭제 때 토큰 철회).
- 연령 등급은 계산값 대신 직접 재정의 가능(새편지는 펜팔 때문에 16+).
- 수동 출시로 두면 승인 뒤 원하는 날 [이 버전 출시].
- **빌드 6 검은 화면**: AppDelegate에 화면 색칠 코드를 넣었다가 꺼짐 → 그 부분은 빼고 알림 연결만 남김.
- 앱 안 결제(StoreKit)는 **새 앱 버전과 함께** 첫 상품 심사.

### 구글
- 새 개인 계정은 **실제 안드로이드 폰으로 Play Console 앱 로그인 기기 확인**이 필요했음(빌린 폰으로 해결).
- 결제 프로필 신원 확인에 주소 증명 → 주민등록등본으로 제출.
- 데이터 보안 양식에 **계정 삭제 URL** 필요(새편지 `/delete-account`).
- 내부 테스트 업로드 실패 줄이 남으면 버튼이 사라짐 → [임시 출시 삭제] → [라이브러리에서 추가].
- 구글 로그인 실패 원인 = 옛 `google-services.json`(구글 로그인 정보 없음) → SHA 넣은 뒤 새로 받기.

## 6. 홍보에서 배운 것

- **만든 사람이 직접 쓴 글**이 브랜드 계정보다 훨씬 퍼짐(Carrier Pidge 사례). 긱뉴스 Show GN·디스콰이엇·대표님 개인 계정.
- 스레드가 반응이 제일 나았음: 짧게, 질문·투표로 끝내기, 해시태그 1개, **링크는 본문 말고 첫 댓글**, 하루 여러 번, 댓글에 빨리 답하기.
- 인스타 격자는 **하루 3개 같은 색**이 예쁨(오방색 돌리기), 그림 글은 한 장 말고 **5장 넘겨 보기**, 인스타 자동 게시는 **JPG만**.
- 모든 글에 스토어 바로 가기 + "링크는 프로필에" 줄.
- 지어낸 후기·가짜 사용자 이야기는 쓰지 않음(연출 영상은 "연출된 가상의 이야기" 표시).
- GitHub 예약 실행은 자주 늦거나 빠짐 → 시각마다 다시 시도 여러 번 + 채널별 기록.
