# 새편지 첫 출시 버전 기획 (앱스토어 심사 제출용) · 2026-10-13 (수정 2회차)

> 작성: Product Planner. 디자이너·개발자·검수가 그대로 받아 쓰는 문서예요.
> 원칙: **완전히 준비해서 출시** (속도 때문에 빼지 않아요). 범위는 **심사 통과와 첫 사용 경험에 필요한 것** 위주예요.
> 유료 새(붕붕이·매)는 별도 문서 `docs/유료새-기획.md`를 따라요.
> **UI Designer 작업은 구청 확인(통신판매업) 뒤에 시작해요. 구청 확인 상황은 작업 전에 먼저 보고해요.**

## 1. 한 줄 정의
**친구에게 새로 편지를 보내면, 실제 거리만큼 걸려 도착해요. 보낸 사람과 받는 사람이 같이 기다려요.**

## 3. 첫 버전 사용자 이야기 5개와 완료 조건

**① 친구와 편지를 주고받는다 (답장 포함)**
- 친구에게 바로 보내고, 받은 편지가 **도착하면 열어서 읽고 [답장하기]**를 누를 수 있다.
- 답장은 **받는 사람이 보낸 사람에게** 새로 날아간다(새·노선을 다시 고른다. 받는 사람 칸은 자동으로 채워진다).
- 링크로만 받은 사람(친구 아님)도 **그 편지의 보낸 사람에게는** 답장할 수 있다(서버 규칙으로 확인, 아무에게나는 못 보낸다).
- 설정의 **"답장" 알림 스위치**를 켜 두면 답장이 왔을 때 알림이 온다.

**② 앱을 닫아도 알림이 온다**
- **도착, 사고(길 잃음·나무 걸림), 친구가 보낸 편지, 답장**이 오면 푸시가 온다.
- 아이폰·안드로이드 **앱에서** 알림이 온다(웹 푸시와 별도로 앱 전용 푸시).
- 설정의 알림 스위치를 끄면 오지 않는다. 처음 한 번 **알림 허용 안내**가 나온다.
- 실제 폰에서 **알림이 뜨는 것까지** 직접 확인한다(검수).

**③ 계정을 연결해서 기록을 지킨다 (구글·카카오·네이버, 애플 검토)**
- **구글, 카카오, 네이버** 중 하나로 **연결**할 수 있다(가입이 아니라 "연결"이라 몇 번 누르면 끝난다).
- 연결하면 **기기를 바꾸거나 앱을 다시 깔아도** 친구·편지·구매가 남는다. 연결 전에는 안내가 한 번 보이고, 건너뛰어도 쓸 수 있다.
- 아이폰에서는 **애플 로그인 제공 여부**를 확정한다(아래 6번, 심사 규정 때문).
- 연결 해제, **앱 안에서 탈퇴와 모든 데이터 삭제**가 된다(애플 규정).
- 수집하는 정보는 **닉네임과 계정 식별 번호만**이고(이메일은 받지 않는 걸 기본으로), 개인정보처리방침에 적는다.

**④ 링크를 보내면 메신저처럼 보이고 바로 열린다**
- 친구 초대 링크나 편지 링크를 **카톡·메신저에 붙이면 아래에 미리보기 카드(제목·그림)가 뜬다**.
- 카드 문구에는 **편지 내용이 들어가지 않는다**(예: "새가 편지를 물고 날아가고 있어요"). 내용 공개는 도착 후 규칙 그대로다.
- 링크를 누르면 **앱이 있으면 앱에서 바로 열리고**, 없으면 웹에서 열린다(앱 설치 후 연결 설정 필요).
- 친구 초대는 기기의 **공유 기능**으로 보낼 수 있다.
- 인터넷이 없으면 **오류 화면 대신 안내와 다시 시도 버튼**이 나온다(심사용).

**⑤ 안전하고 믿을 수 있게 쓴다**
- 받은 편지에서 **신고·차단**이 된다(이미 있음). 신고 처리 담당 연락처가 운영정책에 있다.
- **만 14세 미만** 이용 안내와 결제 제한이 정해져 있다(법무 확정 필요).
- 편지 내용은 **도착 전에는 보낸 사람만** 읽는다(서버 규칙으로 확인).
- 앱 정보에 **상호·대표·연락처(사업자 정보)**와 방침·약관 링크가 있다(표시 범위는 구청 확인 후).
- **유료 새**(붕붕이·매)는 `유료새-기획.md`의 완료 조건을 따른다.

## 4. 하지 않을 기능 (이번 버전)
- **연락처 연결**(법무 검토 후 다음 버전), 전화번호로 친구 찾기
- **사진·파일 첨부**
- **편지 예약(날짜 지정) 발송**
- 뽑기·랜덤 상자, 사고 면제·구제 결제, 구독, 선물하기
- 사람이 직접 뛰는 장난 티어, 언어 설정
- 카카오맵 교체(지금 지도 그대로 출시), 위젯
- 웹에서의 결제(웹은 잠금 표시와 "앱에서 구매" 안내만)

## 6. 소셜 로그인 3종과 법·규정 (조사 결과, 「미확인」 표시)
| 항목 | 내용 |
|---|---|
| 합법 여부 | 소셜 로그인 자체는 합법이에요. 각 서비스 약관과 **개인정보 수집·이용 동의, 처리방침 표기**를 지키면 돼요. 변호사 확인은 별도예요 |
| **애플 규정 4.8** | 구글·카카오 같은 **제3자 로그인으로 기본 계정을 만들거나 로그인하는 앱**은 **"Sign in with Apple" 같은 동등한 옵션**도 제공해야 해요(이름·이메일만 수집, 이메일 비공개 허용, 광고용 수집 없음). 우리 앱은 익명으로도 쓰고 소셜은 "연결"이라 **해당되는지 불분명해요(「미확인」)**. 안전하게 가려면 **애플 로그인도 넣는 것**을 권해요 [(Apple 개발자 포럼)](https://developer.apple.com/forums/thread/765145) |
| 카카오 | 개인정보 동의항목은 **실제 가입 화면과 처리방침을 기준으로 심사**해서, 앱이 실제로 동작하는 수준일 때 신청해야 통과 가능성이 높아요 [(카카오 데브톡)](https://devtalk.kakao.com/t/topic/150829). 이메일 등은 비즈 앱이 필요할 수 있어요(사업자는 있음) |
| 네이버 | 심사 기준은 **「미확인」**. 네이버 개발자센터 공지를 직접 확인해야 해요 |
| 구현 방식 | 카카오·네이버는 **서버에서 확인 후 Firebase 로그인 토큰을 만드는 방식**이 일반적이에요 [(Kakao 로그인 예제)](https://github.com/FirebaseExtended/custom-auth-samples/blob/master/kakao). 서버는 Vercel에 둘 수 있고 유료 전환(Blaze)이 필요한지는 **「미확인」**이에요 |

## 7. 대표님이 결정할 것 (★)
1. **소셜 로그인 범위:** 구글·카카오·네이버 + **애플 로그인 추가 여부**(추천: 추가). 키 발급은 대표님 몫이에요(제가 한 단계씩 안내).
2. **답장 허용 범위:** 링크로만 받은 사람도 보낸 사람에게 답장 가능하게 할까요? (추천: 가능, 그 편지의 보낸 사람에게만)
3. **링크 카드 문구:** 친구 초대 카드에 **닉네임을 넣을지**(예: "○○님이 초대했어요")? 넣으면 내용은 안전하지만 닉네임이 카드에 보여요. (추천: 일반 문구만)
4. **앱 정보에 표시할 사업자 정보 범위:** 구청 확인 뒤에 정해요.

## 8. 위험과 한계
- 심사 반려(웹 껍데기, 4.2, 로그인 규정 4.8): 위 ③·④가 대응이에요. 반려되면 고쳐서 다시 내야 해요.
- 푸시와 앱에서 링크 열기는 **계정 가입 전에는 실제 시험이 불가능**해요.
- 소셜 로그인 3종 + 애플은 **키 발급과 심사가 4개**라서 시간이 가장 많이 걸리는 영역이에요.
- 법적 문서는 **전문가 검토 전에는 정식 문서가 아니에요.**
